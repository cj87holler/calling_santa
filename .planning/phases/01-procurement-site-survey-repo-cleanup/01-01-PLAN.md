<objective>
Build the evidence scaffolding that every other Phase 1 plan writes into, and author it **first** so
no downstream task has to guess what artefact shape it owes.

Purpose: This phase produces no application code. Its entire verification surface is committed
evidence files. Without a verification script authored up front, "record the results" becomes the
instruction, and vague instructions are the dominant failure mode in a procurement phase. The script
is also the phase gate, so its two failure modes both matter: red when it should be quiet (which
trains everyone to ignore it), and green when it should be red (which lets the phase close over
unspent money).

below), the `evidence/` directory tree, a root `README.md` satisfying OPS-01's documentation clause,
a fill-in-the-blank `survey-protocol.md` for the yard visit, and a completed Per-Task Verification
Map. Also corrects the three ROADMAP.md Phase 1 success criteria that CONTEXT.md superseded, and
annotates REQUIREMENTS.md HW-06 with the wired path those decisions admit.

Author `.planning/phases/01-procurement-site-survey-repo-cleanup/verify.sh` and make it executable
with `chmod +x`. Script requirements, all concrete:

Shebang `#!/usr/bin/env bash`. Use `set -u` only. Do NOT use `set -e` — the script must run every
assertion and report all of them, not abort at the first false one. Several assertions are expected
to be false mid-phase.

Resolve the repo root with `git rev-parse --show-toplevel` and change into it so the script works
from any working directory. Set a variable `EV` to
`.planning/phases/01-procurement-site-survey-repo-cleanup/evidence`.

**Four** result helpers writing to stdout — `PASS <label>`, `FAIL <label>`, `PENDING <label>` and
`NOT-YET <label>` — each incrementing its own counter. Print a final summary line in the form
`passed=N failed=N pending=N not-yet=N`.

The three states that are not PASS are semantically distinct and must not be collapsed:

  PENDING  the artefact does not exist yet because the task that produces it has not run
  NOT-YET  the assertion checks state that a *later wave deliberately removes*, so it is
           correctly false right now; the label carries the gating reason
  FAIL     the assertion is false and nothing in the plan explains why

Two modes. Default mode: PENDING and NOT-YET are both reported and neither affects the exit code,
which makes the script usable after every single task commit. With the `--gate` argument: PENDING and
NOT-YET are **both** upgraded to FAIL, because at gate time every wave has run and there is nothing
left to be waiting on. Exit 1 when the failed counter is greater than zero, otherwise exit 0.

Runtime must stay under 2 seconds. Use only `test`, `grep`, `wc`, `ls` and `git`. No network calls,
no `find` traversal over `node_modules`.

Encode these assertion groups in this order.

WAVE 0, always evaluated, never PENDING and never NOT-YET:
`test -d $EV/orders -a -d $EV/site-survey -a -d $EV/spend-controls`; and

`grep -qE 'Order #: *[A-Za-z0-9-]{4,}'`, `grep -qE 'Delivery ETA: *[0-9A-Za-z]'`, and
