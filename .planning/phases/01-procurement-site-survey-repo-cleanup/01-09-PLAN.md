<objective>
Delete `voice/` — after, and only after, the credential it holds has been revoked.

Purpose: OPS-01 asks for delete-or-document and the evidence settles it decisively. `voice/` was
added in the repository's first commit, has never been touched since, is referenced by no source
file, no config, no build script and no document outside `.planning/`, and contains an untouched
duplicate of the Vite starter nested one level deeper. Materially, its `src/main.ts` passes a
standing OpenAI key into browser-side code through `import.meta.env['VITE_OPENAI_API_KEY']`, which
Vite inlines into the client bundle at build time — the exact pattern OPS-02 forbids and the exact
inverse of the token-broker pattern `poc/server.py` already implements. Leaving it in the repository
leaves a worked example of the forbidden pattern where a future agent, or the owner at 11pm in
November, could copy it.

**The ordering is the point.** D-23 fixes it as check, then rotate, then delete. Plan 02 checked.
Plan 06 rotated. This plan deletes. Running `rm -rf` first would remove the untracked `.env` and with
it every record that a live credential ever existed — the key would stay valid on the account,
unaccounted for, drawing on the same balance the Phase 1 spend ceiling was built to protect.

Output: an empty `git ls-files voice`, no `voice/` directory on disk, and no stale reference
anywhere outside `.planning/`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untracked on-disk `.env` -> agent transcript | The last remaining copy of a browser-destined credential; reading it into a log makes the leak durable |
| Repository source -> future agent or future self | A committed worked example of a forbidden pattern is an instruction, whether or not anyone intends it that way |
| Git history -> recoverability | The deletion's safety rests on history retaining the scaffold; a rewrite would remove that safety net for no benefit |
